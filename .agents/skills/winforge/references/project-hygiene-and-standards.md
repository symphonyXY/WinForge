# 程序文件夹管理、模块化开发规范与 Git 安全网

本手册确保 AI 帮用户开发出来的**每一个 Windows 软件项目**都干净整洁、结构一目了然、局部修改不牵连其他功能，且永远有安全可回退的版本存档。

---

## 1. 标准项目文件夹结构（严禁乱堆根目录）

新建软件项目时，按以下清晰分区组织文件夹（按实际技术栈微调后缀，但**大分区思路不变**）：

```text
<软件项目名>/
├── README.md                 # 大白话中文说明：软件用途、怎么运行、怎么重新打包 .exe
├── .gitignore                # 自动忽略依赖包、构建缓存、临时日志，绝不把垃圾塞进版本记录
├── package.json / *.csproj   # 项目主清单（放在根目录的配置文件保持最少）
├── src/                      # 【源码区】所有程序代码都在这里，按职责拆干净
│   ├── main/                 # 窗口控制、本地文件读写、托盘/系统集成（后台逻辑）
│   ├── styles/               # 视觉体系核心：颜色变量、玻璃材质、圆角/字号、弹簧动效曲线
│   ├── components/           # 可复用高颜值控件：融合顶栏、按钮、开关、滑块、原子卡片、灵动岛
│   ├── features/             # 按功能模块拆分（如 timer/、settings/、exporter/）
│   └── utils/                # 纯工具函数（日期、格式转换、路径安全处理）
├── assets/                   # 【静态素材区】离线内置字体、软件图标 .ico/.png、SVG 图标
├── docs/                     # 【说明区】需求记录、后续迭代计划（按需创建，不放空文件夹）
└── release/                  # 【成品交付区】打包好的 Setup.exe 安装包集中放这里，一眼就能找到
```

### 根目录洁癖红线
- ❌ **严禁在项目根目录散落**：临时调试脚本（`test.js`、`try.py`、`debug.bat`）、随手截的图（`1.png`、`screenshot.png`）、报错日志（`error.log`）、备份副本（`app_old.js`、`index_bak.html`、`copy.css`）。
- ❌ **严禁留空壳垃圾**：不再使用的旧组件、死代码、重复图片必须在核实无引用后清理干净，不要注释掉一大坨几百行废代码留在文件里充数。

## 2. 模块化代码规范（让 Vibe Coding 改一处不崩全局）

- **拒绝“巨无霸单文件”**：严禁把界面 HTML、样式 CSS、全部业务逻辑和窗口系统控制塞进同一个一两千行的文件里。
  - **视觉样式独立**：颜色、玻璃透明度、圆角、阴影、动画曲线全部抽到 `src/styles/tokens.css`（或同等的主题变量文件），以后用户说“把玻璃再透一点”“圆角再圆一点”，只改一处全软件同步生效。
  - **单文件聚焦一件事**：一般单个组件或功能文件尽量控制在 **300 行以内**；超过时自然拆分子组件或辅助模块。
- **文件与目录命名清晰统一**：
  - 全部使用简洁明了的英文小写（如 `title-bar.tsx`、`apple-tokens.css`、`file-organizer.ts`），不要出现中英夹杂、带空格或 `new2`/`final_v3` 这类模糊命名。
- **关键位置写简明中文注释**：
  - 在每个核心文件顶部用 1–2 句中文写明“这个文件负责什么”；
  - 在视觉核心参数（玻璃层、弹簧曲线）、打包配置、系统路径处理处附简明中文备注，让用户自己打开文件也能大致看懂。
- **失败路径稳健处理**：
  - 读不到文件、权限不足、断网、用户点取消时，绝不让软件直接闪退白屏，而是给出友好中文提示和可点的“重试/返回”按钮。

---

## 3. 安全清理与防误删规矩

- **临时垃圾主动清**：开发或打包过程中 AI 自己新建的临时验证脚本、临时缓存文件，任务收尾前必须清理干净，不留尾巴。
- **已有文件绝不私自删**：如果要清理项目中**原本就存在的旧文件、废弃资源或可能包含用户数据的文件**，必须先用通俗中文列出清单：
  - 文件路径 + 它原本是干嘛的 + 为什么确认现在没用了
  - **等用户明确点头后才能删除**。
- **严禁危险清场命令**：绝不未经确认执行递归清空或强制重置命令覆盖用户的个人数据与未保存修改。

---

## 4. Git 版本安全网（随时留好“后悔药”）

很多 Vibe Coding 翻车都是因为“本来好好的，一顿大改把前面满意的版本改坏了还退不回去”。AI 必须主动帮用户守住这条安全网：

1. **新项目起步即初始化**：建好目录骨架、写好 `.gitignore` 后，顺手帮用户做好第一次干净的 Git 提交（`init: 搭建初始项目骨架`）。
2. **三个必须提醒/执行存档的时机**：
   - 刚刚跑出让用户满意的最小可运行雏形时；
   - 准备动手做**大规模视觉换肤、核心重构或文件大整理之前**（先存一版再动手）；
   - 每次成功打包出一个好用的 `.exe` 正式版本后。
3. **提交信息用简明中文**：例如 `feat: 完成 Apple 液态玻璃主界面与倒计时核心功能`、`style: 精修按钮按压回弹手感`，让用户翻历史记录时一眼看得懂每一版长什么样。
4. **随时可一键后悔**：当用户说“改崩了，退回刚才满意的那一版”时，先确认是否需要保留刚写的新素材，再安全回退到对应存档点。
